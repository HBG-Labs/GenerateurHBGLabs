# P2.3 — Deterministic CreativePlan → MotionSpec Compiler

## Objectif et frontière

P2.3 raccorde le Creative Director déterministe au moteur P1 sans introduire de renderer, d’IA ou de réseau dans le bridge.

```text
PlannerInput fixture
    ↓
P2.2 Story / Scene Planner
    ↓
CreativePlan 0.1.0
    ↓
CreativeResolution 0.1.0
    ↓
Creative Compiler 0.1.0
    ↓
MotionSpec 0.2.0
    ↓
P1 validation + compiler + preflight
    ↓
RenderPlan / AudioPlan / SubtitlePlan
    ↓
Remotion renderer
    ↓
MP4
```

Le package `@motion-engine/creative-compiler` dépend de `creative-core` et de `core`. L’inverse est interdit : `creative-core` reste indépendant de P1, et P1 reste indépendant de P2.

Le Creative Compiler ne produit ni JSX, ni React, ni CSS arbitraire, ni frame renderer-specific. Il ne lance ni Chromium, ni FFmpeg. Sa seule sortie exécutable est un `MotionSceneSpec` P1 validé.

## Contrat de compilation

```ts
compileCreativePlan(plan, {
  resolution,
  profile,
  resolved_style,
  pattern,
  platform,
})
```

Le résultat contient :

- `motion_spec` ou `null` ;
- `provenance` ou `null` ;
- un fingerprint du compilateur ;
- un `CreativeCompileReport` structuré ;
- `ok`, qui n’est vrai qu’en l’absence d’ERROR.

P1 revalide toujours le MotionSpec. P2.3 ne peut pas s’auto-déclarer compatible avec P1.

## CreativeResolution 0.1.0

La résolution est un sidecar provider-agnostic. Elle ne modifie pas CreativePlan et associe explicitement :

- un `ContentSlot` à une scène, un texte et ses canaux ;
- un `AssetIntent` à une référence locale/content-addressed ;
- éventuellement un `AudioEventIntent` à un cue P1.

Les slots splittés peuvent recevoir un contenu distinct par scène. Le texte vient exclusivement d’une fixture ou d’une résolution externe. Aucun `Lorem ipsum`, slogan, URL, média ou cue n’est inventé.

Politique stricte :

- contenu obligatoire unresolved → ERROR ;
- asset obligatoire unresolved → ERROR ;
- source requise sans `source_slot` → ERROR ;
- narration requise sans contenu parlé → ERROR ;
- SFX requis sans cue résolu → ERROR ;
- music/ambience obligatoire sans contrat P1 compatible → ERROR.

La voix P1 reste estimée et sans asset audio. Aucun TTS ou alignement phonémique n’est simulé.

## Compilation profile versus style

`short_form_default@0.1.0` décrit les règles de traduction :

- visual intent → stratégie de layout ;
- motion character → behaviors P1 ;
- rôle typographique → token P1 ;
- transition intent → frontière P1 ;
- rôle narratif → phase rythmique et purpose P1 ;
- plateforme générique et version MotionSpec cible.

Le style reste une entrée distincte. Le même CreativePlan est compilé avec :

- Signal : `p14_signal@1.0.0` ;
- Nocturne : `control_nocturne@1.0.0`.

Le profil ne contient aucune logique de marque ou de plateforme commerciale.

## Traduction visuelle

Mappings principaux :

| VisualIntent | Stratégie P1 |
|---|---|
| `text_dominant`, `statistic`, `quote` | `text_stack` |
| `image_dominant`, `reveal`, `background_visual` | `image_hero` |
| `mixed`, `iconographic` | `split` |
| `comparison` | `comparison` |
| `diagram` | `diagram` |
| `abstract` | `abstract` |

Les placements restent exprimés sur la grille sémantique P1. Les pixels, safe zones, glyphes, line breaks finaux, crops et tracks sont résolus par P1.

`diagram → illustration + constraint diagrammatic` reste inchangé. P2.3 ne modifie pas P2.1 pour embellir le modèle.

Les images utilisent `cover` pour `image_hero` et `contain` pour les compositions split/diagram/comparison, afin de préserver le ratio et éviter un crop artificiel. Le focal point ou la région sémantique vient de la résolution d’asset.

## Typographie

Les rôles P2 sont traduits vers les tokens P1 :

- display/statistic → `type.display.xl` ;
- headline → `type.display.l` ;
- quote → `type.display.m` ;
- body → `type.body` ;
- caption → `type.subtitle` ;
- CTA → `type.headline`.

P2.3 découpe seulement les chaînes aux limites structurelles MotionSpec. HarfBuzz, la typographie française, le shaping, le fitting et l’overflow restent exclusivement dans P1.

## Motion et transitions

Les caractères motion utilisent uniquement `REVEAL_TEXT`, `CAMERA_PUSH` et `FOCUS_REGION` lorsqu’une région est réellement disponible. Aucun behavior nouveau n’a été ajouté.

P1 ne possède actuellement qu’une frontière inter-scène fiable et explicite : `CUT`. Les transitions `smooth`, `energetic`, `dramatic`, `reveal` et `continuation` sont donc conservées comme CUT avec un diagnostic `creative_compile.transition_degraded_to_cut`. Pour `reveal`, un `MASK_WIPE` intra-scène peut être ajouté au layer image ; il n’est pas présenté comme une transition inter-scène équivalente.

## Temps et quantification

Le CreativePlan fournit des secondes sémantiques ; P2.2 fournit des millisecondes entières par scène. P2.3 réalloue le budget total en millisecondes entières par méthode du plus fort reste :

```text
sum(scene.duration_ms) === target_duration_ms
```

La quantification de diagnostic utilise les frontières cumulées :

```text
boundary_frame = round(cumulative_ms × fps / 1000)
scene_frames = next_boundary - current_boundary
```

Il n’y a donc aucun arrondi indépendant cumulatif. Le MotionSpec conserve les millisecondes ; P1 reste l’autorité qui produit les frames finales avec la même règle cumulative.

## Provenance

`CreativeCompileProvenance 0.1.0` relie :

```text
Creative scene → MotionSpec scene
ContentSlot / AssetIntent / VisualIntent → MotionSpec layer
MotionSpec scene → frontières quantifiées
```

Les IDs sont dérivés canoniquement. Aucune horloge, randomness ou UUID n’intervient.

Le fingerprint inclut :

- version du Creative Compiler ;
- ID, version et hash du profil ;
- ID, version et hash du style ;
- hash CreativePlan ;
- hash CreativeResolution ;
- version MotionSpec cible.

Aucun timestamp n’est hashé.

## Diagnostics et preflight

Le format P2.1 est réutilisé : code, severity, path, node/scene, contexte et action suggérée.

Le preflight couvre notamment :

- résolution contenu/assets/audio ;
- cohérence de provenance ;
- limites textuelles ;
- sources factuelles ;
- visual/motion/transition/type mappings ;
- style/pattern/profile ;
- durée impossible ;
- narration et sous-titres ;
- validation structurelle et sémantique MotionSpec P1.

Le render gate P1 vérifie ensuite `requirements ⊆ renderer.capabilities`. Un renderer sans `IMAGE` refuse la sortie avant rendu.

## Fixtures et goldens

Fixtures compilées jusqu’au RenderPlan :

- Hypothetical 30 s ;
- Explainer 30 s ;
- Product Demo 20 s ;
- Minimal 5 s ;
- Long 60 s.
- Invalid : arrêté par le Planner avec des diagnostics `ERROR`, avant création d’un CreativePlan ou d’un MotionSpec.

La fixture principale contient des textes français versionnés et des mappings explicites vers l’asset local CC0 P1.4. Ces textes sont des données de test, pas une génération automatique.

Les goldens P2.3 contiennent MotionSpec, provenance, diagnostics, fingerprints et hashes P1. Leur mise à jour exige :

```text
npm run golden:update:p2.3
```

Le mode normal `golden:verify:p2.3` est strictement read-only.

Les références visuelles P2.3 sont séparées des goldens P1. Leur mise à jour exige explicitement `UPDATE_P23_VISUAL_GOLDENS=1` lors du rendu P2.3.

## Preuve réelle 1080×1920

La fixture hypothétique produit 900 frames à 30 FPS pour Signal et Nocturne.

Premier run Windows :

- Signal : RenderPlan `023322a07d5ac6e2dd82ddb0f0771361247ebc2c6182fc7caa32942eaea7fe51` ;
- Nocturne : RenderPlan `3b63dfa8abf6009af74d50cfef6ad5e93ddb0aab84e8833740e7ed22cb47542b` ;
- visual regression : PASS sur dix frames ;
- bundle Nocturne : réutilisé, `bundle_ms = 0` ;
- warnings P1 : `contrast.unknown_on_image`, attendu et non bloquant.

Les MP4, plans, rapports, frames, contact sheet, métriques et hashes d’intégrité sont écrits sous `out/p2.3/reference/` et restent ignorés par Git.

## Limites connues

- Le contenu et les assets doivent être résolus avant compilation stricte.
- Aucune recherche, génération, traduction ou vérification factuelle n’est effectuée.
- Aucune voix/SFX/musique réelle n’est produite.
- Les transitions inter-scènes non-CUT sont dégradées explicitement et diagnostiquées.
- Le contraste sur image reste inconnu sans analyse pixel ; aucun score n’est inventé.
- La fixture visuelle locale prouve le pipeline, pas une direction artistique finale.
