# P3.2 — Premium Motion Vocabulary

Status: deterministic, provider-free vocabulary layer built on the certified P3.1 grammar and P1.7 dynamic typography.

## Architecture

The dependency direction remains one-way:

`Creative Core → Visual Core 0.2.0 → Visual Compiler 0.2.0 → P1 Core / P1.7 → passive renderer`

P3.2 is additive. VisualPlan 0.1.0, VisualGrammar 0.1.0, Visual Compiler 0.1.0, and the certified P3.1 registries remain available and retain their fingerprints. VisualPlan 0.2.0 opts into the P3.2 registries and P1.7 behavior registry. The legacy P2 path remains `CreativePlan → P2.3 → MotionSpec → P1` and does not depend on Visual Core.

No provider, network client, generated code, arbitrary CSS, shell command, Blender dependency, GPU API, or external asset source is used. The contract remains `data → strict validation → deterministic plan`.

## P3.1 → P3.2 capability gap

| Area | P3.1 | P3.2 certified scope | Still future |
|---|---|---|---|
| Typography | reveal, scale accent, run-safe words | animated tracking, `wght`, `wdth`, type/mask phrases, critical-state HarfBuzz fitting | arbitrary per-character/per-cluster choreography |
| Morphing | semantic scale/mask bridge | versioned semantic chains and topology-limited parametric validation | arbitrary path/mesh morph |
| Continuity | anchors and three bridge families | five consecutive bridges, frame/type/camera continuity metadata, persistent entity handoff | overlapping general inter-scene compositor |
| Camera | bounded push/follow approximation | depth surge, settle, deterministic camera continuity | true 3D camera and general path-follow |
| Choreography | phase events | named MotionEvents, causal relations, sync anchors, anticipation/impact/settle metadata | probabilistic direction |
| Compositing | layer order, masks, depth | stronger occlusion, frame/portal and shape-to-mask composition | advanced blend-mode/effect engine |

No fundamental P1 change was required after P1.7. General path-follow, general overlapping scene compositing, cluster choreography, and arbitrary morphing remain explicitly unsupported.

## Versioned vocabulary

VisualGrammar `0.2.0` has separate fingerprints for patterns, MotionPhrases, SceneBridges, and camera definitions. Registry closure is enforced by VisualPreflight; unknown IDs or versions fail.

New pattern families include dynamic tracking, variable weight and width, word-to-mask, shape-to-mask, circle-to-portal, frame expansion, dot-to-orbit, vector assembly, and causal diagrams. New phrases include tracking impact, axis pulse, word/mask bridge, semantic morph chain, causal path impact, camera depth surge, occlusion reveal, frame portal transform, overlap/follow-through, and intentional impact cut. The combined phrase registry contains at least fifteen distinct definitions.

The additional bridge registry supports `FRAME_EXPANSION`, `ZOOM_THROUGH`, and `TYPE_SCALE_THROUGH`. P3.2’s reference uses only validated consecutive boundaries. A bridge classified `compatible_simplified` is reported honestly; it is never presented as arbitrary geometry morphing. Chosen premium bridges compile to an explicit supported transition and never silently degrade to CUT.

## Advanced kinetic typography

P3.2 resolves dynamic typography only on explicitly selected shaped runs. The resolver never uses `text.split("")` and never separates ligatures, accents, combining marks, or HarfBuzz clusters. Tracking, weight, and width are choreographed in bounded successive states so the visual sequence remains expressive without exceeding P1’s concurrent render/attention budget.

P1.7 remains the authority for axis availability/ranges, shaping, glyph coverage, critical-state measurement, intermediate overflow, fitting, safe zones, and RenderPlan requirements. The reference font supports `wght` and `wdth`; unsupported axes are errors. Dynamic typography is opt-in and is not applied to every text layer because reshaping costs more than static text.

## Morphs and transformation chains

`MorphChain` has stable IDs, one persistent entity identity, a declared `parametric` or `semantic` kind, and ordered phase-bound steps. Parametric compatibility is deliberately narrow: dot/ellipse and rect/frame families only. Incompatible topology fails VisualPreflight. Semantic chains combine validated transforms, path progress, masks, and continuity rather than claiming geometric interpolation.

The Blue Sky reference includes `line → path`, `dot → ellipse → mask`, `type → frame`, and `dot → ellipse → portal` semantic chains. These are visual-causality declarations backed by rendered P1 behaviors, not executable code.

## Choreography and causality

MotionEvents have stable IDs, local targets, phases, energy direction, and optional sync anchors (`IMPACT`, `REVEAL`, `BRIDGE_CROSS`, `PAYOFF`). Causal relations are allowlisted as `TRIGGERS`, `FOLLOWS`, `OVERLAPS`, `PREPARES`, or `REVEALS`. Missing events and targets fail preflight.

The reference arc is `opening → build → escalation → breath → payoff`. The scattering sequence explicitly models path arrival, radial impact, and mask reveal. The horizon scene preserves a static hold before the portal/payoff movement. Sync anchors are metadata for a future Sound Director; P3.2 has no audio dependency.

## Camera, depth, and compositing

Depth continues to use an acyclic foreground/midground/background graph with parallax factors and explicit occlusion. Camera movement is resolved to bounded P1 transforms; layers at different depth planes receive different declared camera intensities rather than one global scale. `CameraContinuity` preserves conceptual energy, velocity intent, and scale momentum across an adjacent boundary.

The model is honest 2.5D. It contains no true 3D scene, lighting, material, Blender call, shader, or GPU requirement. Effects remain disabled for this certification because stable cross-platform implementations were not established; attempting to use one produces `visual.effect.future`.

## VisualPreflight 0.2 scope

Before MotionSpec, preflight validates registry fingerprints, target types, exclusive-control conflicts, depth cycles, anchor/entity continuity, morph compatibility, MotionEvent references, causal relations, LayoutTransition targets, camera continuity, limits, and unsupported effects. P1 then independently validates temporal budgets, typography axes, HarfBuzz fitting, mid-animation states, engine limits, and capabilities.

P3.2 does not duplicate P1 fitting or timing logic. P1 stays the final authority.

## Reference sequence

The deterministic film remains “Pourquoi le ciel est-il bleu ?” so visual progress can be compared against P2 and P3.1 without changing subject. It uses controlled synthetic shapes, paths, masks, text, and the `spectral_motion` token style.

Three designed review moments are declared:

1. Typography: run-safe reveal → tracking burst → weight pulse → width expansion → type/frame transition.
2. Continuity: ray arrival → radial scatter → semantic shape/mask chain → full-frame reveal.
3. Depth/camera: independently scaled depth planes → foreground occlusion → camera momentum → portal/payoff settle.

These moments belong to one explanatory sequence; they are not independent effect demos.

## Security, determinism, and cost

All IDs, registry selections, plan hashes, tracks, critical states, and output hashes are deterministic. Cross-process compilation must match. The RenderPlan requires `DYNAMIC_TYPOGRAPHY` only where used. Payload schemas are strict, arrays bounded, unknown behavior rejected, and effects/provider/media paths remain closed.

Render-cost metadata stays descriptive (`LOW`, `MEDIUM`, `HIGH`). It is not pricing. P3.2 records compile, render, FPS, memory, tracks, keyframes, paths, masks, phrases, bridges, morph chains, causal relations, and dynamic typography tracks.

## Benchmark and future boundaries

The supplied [Will Taylor showreel](https://youtu.be/RB0X7CojhZ8), [Denis Gimaev showreel](https://youtu.be/jkPVT55GAOo), and [3D motion-design showreel](https://youtu.be/wCqcJU1YpKk) are qualitative references only. They are not fixtures, assets, templates, visual goldens, or compositions to reproduce.

Remaining gap includes synthetic-only assets, no generated media, no image understanding, no true 3D/Blender, no advanced particles/lighting, no sound design, no arbitrary path morph, no overlapping general compositor, no Visual Critic, and no probabilistic Visual Director.

P3.3 may later introduce a provider-agnostic Visual Director that selects only registered patterns, phrases, bridges, camera moves, depth intents, and pacing. Its structured output will require local validation and targeted repair. P3.2 implements none of that provider behavior.

Future boundaries remain:

- `VisualPlan → future 3DScenePlan → controlled Blender adapter → rendered layers → P1 compositing`;
- `Image → future Image Understanding → semantic layers/depth → VisualPlan`;
- `Rendered frames → future Visual Critic → structured diagnostics → targeted visual repair`;
- `Visual timing → future Sound Director → AudioPlan`.

Local GPU remains optional; P3.2 requires none. A future model must never emit arbitrary Blender Python, JSX, JavaScript, shell commands, or shaders for direct execution.
