# P1.4 — Stratégie de régression visuelle

Les références sont produites par `npm run render:p1.4` dans `out/p1.4/` :

- `p1-4-signal.mp4` et `p1-4-nocturne.mp4`, 540×960 à 30 FPS ;
- une frame stable de chaque style et `p1-4-comparison.png` ;
- `p1-4-signal-1080x1920.png` pour le contrôle typographique cible ;
- plans, manifestes, métriques, empreintes et état Git du run.

Sur l'environnement de référence, `visual-regression.json` conserve un SHA-256
exact de chaque PNG. Une égalité exacte est attendue quand OS, navigateur,
fonts et toolchain sont identiques.

Entre environnements, l'égalité PNG n'est pas une preuve fiable à cause du
rasterizer et du navigateur. `integration/visual-regression.ts` fournit donc
une comparaison RGB normalisée avec trois limites simultanées : erreur absolue
moyenne, RMSE et ratio de pixels dont un canal dépasse le seuil. Les seuils
initiaux conservateurs sont versionnés dans le code et dans le rapport du run.
Une image n'est acceptée que si les trois limites sont respectées.

La planche côte à côte reste obligatoire pour la revue humaine des différences
de composition que la métrique ne qualifie pas : hiérarchie, crop, focus,
rythme visuel et lisibilité.

Un run sale inscrit `git_dirty=true` et `reference_eligible=false`. Les
références finales sont régénérées après le commit local, depuis un worktree
propre ; les outputs restent ignorés par Git.
