# P1.7 — Dynamic Typography Foundation

## Statut et motivation

P1.7 est une extension additive de P1 destinée à rendre animables deux propriétés jusqu’ici statiques : le tracking et les axes de fonte variable autorisés. Elle ne reprend pas P3.2 et n’ajoute ni path-follow général, ni compositor inter-scènes, ni morph arbitraire.

Le défaut initial était contractuel : `tracking_px`, `wght` et `wdth` existaient dans les runs façonnés, mais pas dans l’allowlist des tracks. Le renderer peignait donc une valeur unique par run.

## Contrats et compatibilité

- Un plan sans typographie dynamique reste un `RenderPlan 0.3.0`, compilé par `0.5.0`, avec les mêmes hashes historiques.
- Un plan contenant `tracking_px`, `font_axis.wght` ou `font_axis.wdth` devient un `RenderPlan 0.4.0`, compilé par `0.6.0`.
- Le renderer historique reste `0.5.0` avec ses capabilities historiques.
- L’opt-in P1.7 utilise le renderer `0.6.0` et la capability `DYNAMIC_TYPOGRAPHY`.
- Les tracks dynamiques sont interdites dans un plan `0.3.0`; un comportement inconnu reste rejeté.

Cette sélection conditionnelle évite une migration silencieuse des références Signal, Nocturne et P1.6.

## Tracks

`TYPE_TRACKING@1.0.0` produit une track `tracking_px` ciblant un `source_run`. Ses paramètres sont exprimés en em puis résolus en pixels par le Core. La plage défensive est `[-0.2em, 0.5em]`.

`TYPE_AXIS@1.0.0` produit une track `font_axis.<tag>`. P1.7 ferme le registre aux tags `wght` et `wdth`. Chaque fonte déclare ses axes depuis la table OpenType lue par HarfBuzz. Un axe absent ou une valeur hors de `[min, max]` est une erreur structurée; il n’existe aucun fallback silencieux.

Les noms d’axes, les valeurs CSS et `font-variation-settings` proviennent exclusivement des données P1 validées. Aucune chaîne CSS arbitraire n’est acceptée.

## HarfBuzz, shaping et fitting

HarfBuzz reste l’autorité pour les glyphes, ligatures, accents, kerning, clusters, métriques et axes variables. Pour chaque état critique, P1 recompose le run avec :

- hash et bytes de fonte ;
- taille ;
- axes triés ;
- tracking ;
- locale ;
- texte et configuration de shaping.

Chaque état est remesuré contre la largeur et la hauteur réelles du box. Un état qui déborde produit `text.dynamic_overflow`. Les protections `font.missing_glyph`, `font.axis_unsupported`, `font.axis_out_of_range` et les erreurs de shaping restent bloquantes.

## Politique des états critiques

La politique `bounded_frame_sampling_v1` analyse :

1. toutes les frames de keyframes ;
2. les bornes de la fenêtre animée ;
3. un échantillonnage uniforme, déterministe et borné de l’intervalle restant.

La limite par défaut est de 96 états, avec un maximum contractuel de 128. Cette politique capture les extrema explicites et les overshoots spring observables aux points échantillonnés. Elle n’est pas présentée comme une preuve analytique universelle pour toute fonte variable ou toute courbe future. Le renderer applique ensuite exactement le même évaluateur déterministe que l’analyse P1.

## Cache et mémoire

Le cache de shaping est FIFO et borné à 2 048 états. Le cache des fontes/variations chargées est FIFO et borné à 512 états. Une clé de shaped state comprend toutes les entrées qui influencent la forme ou les métriques; elle n’est jamais basée uniquement sur le texte.

## Renderer passif

Le Core décide : validation, easing, temps, valeurs, fitting, axes et capabilities. Le renderer ne fait que résoudre la valeur de track déterministe pour la frame et appliquer `letter-spacing` et une liste triée de `font-variation-settings`. Il ne choisit ni axe, ni fallback, ni seuil de lisibilité.

## Cluster safety — OPTION B: deferred

P1 conserve déjà dans chaque `PlanRun` les glyphes HarfBuzz, leurs clusters, advances et offsets. L’audit confirme les frontières monotones de graphemes, les ligatures et les combining marks.

La choreography per-cluster n’est pas ajoutée en P1.7. Le renderer certifié peint encore un run façonné comme une unité browser. Exposer des transforms par cluster sans divergence entre le shaping HarfBuzz et le layout browser demanderait un renderer dédié de clusters/glyphes, avec positionnement absolu et nouvelles preuves de fitting. Une séparation `text.split("")` casserait les ligatures, clusters et accents et reste interdite.

P3.2 peut donc utiliser les runs/mots déjà façonnés, le tracking dynamique et `wght`/`wdth`, mais ne peut pas revendiquer une choreography arbitraire par caractère.

## Limites P1.7

- 128 tracks typographiques dynamiques par plan ;
- 2 axes dynamiques par run ;
- 96 états critiques par défaut, 128 au maximum ;
- axes allowlistés : `wght`, `wdth` ;
- 2 048 shaped states et 512 font/variation states en cache.

Les nombres non finis, propriétés inconnues, axes arbitraires et valeurs hors plage sont rejetés. Aucun réseau, provider, code dynamique, `eval`, script shell ou dépendance GPU n’est introduit.

## Performance et preuve

`npm run certify:p1.7` mesure de façon informative les variantes STATIC, TRACKING, WGHT, WDTH et COMBINED ainsi que la mémoire Node. `npm run render:p1.7` produit le film de 7 secondes et les frames start/mid/end/hold. Ces chiffres ne constituent pas un SLA.

`npm run check` vérifie le nouveau golden sémantique, les tests P1.7, les goldens historiques P1/P2/P3.1, l’isolation, la contamination et les smokes renderer. La CI Linux dédiée ne requiert aucun secret ni GPU local.
