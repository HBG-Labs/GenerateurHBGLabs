# Procedural asset language guide

This guide defines the compact language available to a future provider. It is not a provider prompt.

## Selection order

1. Choose an `AssetLanguage`: UI, data, vector illustration, editorial or procedural environment.
2. Select a registered family and compatible variant.
3. Declare semantic role, emphasis and density.
4. Select a supported material language/material.
5. Select a compatible choreography and persistence intent.
6. Let the deterministic resolver build IDs, hierarchy, components, geometry and motion targets.

## Choreographies

- `PRODUCT_HERO`: assemble → focus → extract → reassemble.
- `DATA_HERO`: assemble → focus → expand.
- `EDITORIAL_RECOMPOSE`: assemble → focus → reassemble.
- `ENVIRONMENT_FOCUS`: assemble → focus → expand.

These stages reuse existing timelines and motion phrases. They are not a parallel temporal engine.

## Directional variants

The same family can respond coherently to direction through density, emphasis, system identity and material language. Product-polished favors layered surfaces and component focus; editorial-precise reduces radii and uses restraint; explainer-luminous favors layered environment fields and causal paths. Style still owns palette and typography tokens.

## Least authority

A future provider may select family, variant, material intent, density, emphasis and choreography from active IDs. It may not emit component trees, component IDs, SVG, arbitrary paths, URLs, pixel geometry, CSS, keyframes, scripts or renderer settings.

## Honest availability

Supported and simplified capabilities are distinguished in the context. Unsupported image, subject-cutout, photography and 3D requirements must produce a diagnostic or an explicitly registered alternative. No silent primitive fallback is allowed.

## Targeted repair

Stable request, asset, component, material and choreography IDs permit future repair to target one decision without regenerating the full sequence. Component bounds, hierarchy, focusability, density and material metadata are retained for a future Visual Critic, but no probabilistic QA exists in P3.3.5.

## Product value

- **Visual:** richer, coherent surfaces instead of isolated primitive fixtures.
- **Motion:** components remain addressable for assembly, focus, extraction, carry and reassembly.
- **Product:** deterministic, provider-free assets can later be edited by changing copy, values, density, visibility or style without regenerating a bitmap.
