# P1.6 — Certification / cross-platform / production readiness

## Objectif et périmètre

P1.6 certifie le moteur déterministe livré par P1.1–P1.5. Elle n’ajoute ni
génération IA, ni provider, ni direction créative, ni produit public. Le Core
reste indépendant de React/Remotion et `examples/rezo360` reste un consommateur
secondaire sans dépendance inverse.

Base auditée : branche `feature/social-motion-engine`, commit P1.5
`8a6bfd7dd1565b7b0fc0e15fb81f732aa8a84493`, tree propre avant travaux.

## Architecture certifiée

Le pipeline demeure : validation, temporal, layout, typographie, assets,
behaviors, AudioPlan, SubtitlePlan, preflight, RenderPlan, graphe de dépendances
et manifeste. `profileCompileForRender()` observe ces phases sans injecter ses
mesures dans les documents déterministes. Le renderer ne reçoit que des plans
résolus et refuse toute capability absente avant bundling.

Le manifeste passe à `0.4.0` afin d’ajouter `package_manager` et
`lockfile_sha256`. Son hash complet reste spécifique à l’environnement. La
projection `semantic-certification-fingerprint 0.1.0` exclut exclusivement
l’horodatage, Git et la toolchain hôte ; elle conserve plans, diagnostics,
graphe, IDs, fonts, assets, renderer, configuration et versions sémantiques.

## Déterminisme

- **Semantic determinism — strict** : RenderPlan, AudioPlan, SubtitlePlan,
  DependencyGraph, diagnostics, IDs stables et projection sémantique du
  manifeste doivent correspondre exactement au golden versionné.
- **Render determinism — toléré et mesuré** : dix frames (ENTER, ACCENT,
  SETTLE, HOLD, EXIT pour Signal et Nocturne) sont comparées en RGB normalisé.
- **Binary determinism — non revendiqué** : les MP4 peuvent différer entre
  Chromium/FFmpeg/OS sans différence de composition.

Le golden sémantique est vérifié par `npm run golden:verify:p1.6`. Sa mise à
jour exige `npm run golden:update:p1.6`. Les images exigent séparément
`npm run golden:update:visual:p1.6`. Aucun test ordinaire ne réécrit une
référence.

Sur Windows et Ubuntu, les fingerprints finaux correspondent strictement :

- Signal : `870930b3c78786bdebba3ed69b65868023b8c0033267d9f4f1d233140e5ef5ef` ;
- Nocturne : `ec7fb911d24a8161169a495b9fb05ac402d750e6d68c079b3b1c68d4a31cd48f`.

RenderPlan, AudioPlan, SubtitlePlan, DependencyGraph, diagnostics, IDs stables
et projection sémantique du manifeste ont donc la même empreinte sur les deux
plateformes. Les MP4 binaires diffèrent et le déterminisme binaire reste non
revendiqué.

## Régression visuelle

Métriques simultanées, versionnées dans `certification/goldens/visual-policy.json` :

- MAE RGB normalisée ≤ 0,012 ;
- RMSE RGB normalisée ≤ 0,035 ;
- ratio de pixels dont un canal diffère de plus de 12/255 ≤ 0,08.

Ces seuils partent de la politique P1.4 et tolèrent surtout la rasterisation de
glyphes entre navigateurs/OS. Ils peuvent produire des faux positifs après une
mise à jour Chromium et des faux négatifs sur une différence perceptuelle très
localisée. La planche de contact et la validation humaine restent obligatoires.

## Typographie

La certification verrouille la font variable Noto Sans Mono par SHA-256, les
axes `wght`/`wdth`, les glyph IDs, clusters, positions, avances, métriques,
wrapping, fitting et taille minimale sur un corpus français comprenant :
`Électricité`, `L'intervention est terminée.`, `1 249,90 €`,
`Aujourd’hui, votre équipe intervient à Fort-de-France.` et un cas de ligature.
Les nombres groupés et unités monétaires utilisent désormais des espaces fines
insécables. Aucun fallback système n’est autorisé.

## Performances

Les métriques distinguent mesures et observations : temps total et par phase,
shaping inclus dans `resolve_typography`, bundle, réutilisation du bundle,
render, FPS, octets et pic RSS Node. Les mémoires Chromium et FFmpeg restent
`null` faute de mesure fiable et portable. Les gates fonctionnels sont stricts ;
les performances CI sont informatives. Le ratio catastrophique documenté est
3×, mais il n’est pas activé sur runners partagés afin d’éviter un benchmark
fragile lié à la machine.

Baseline observée sur le runner Linux final : compilation Signal `24,77 ms`,
compilation Nocturne `11,49 ms`, bundle initial `7,42 s`, bundle Nocturne
réutilisé (`0 ms`), rendu Signal `16,85 s` à `12,46 fps`, rendu Nocturne
`15,46 s` à `13,58 fps`, pic RSS Node `1 123 086 336` octets. Ces mesures ne
déclenchent aucun gate catastrophique et restent propres à ce runner partagé.

## Failure injection et sécurité

Les suites couvrent ressources absentes/corrompues, SVG hostile, path invalide,
focal point, traversal, racine d’assets, hashes incohérents, RenderPlan/manifeste
invalides, style non bumpé, capabilities absentes, EngineLimits, Chromium
indisponible, échec de destination et interruption injectée. Le renderer écrit
dans un temporaire unique, valide, renomme, puis nettoie ; une interruption ne
publie aucun fichier final ni `.partial` résiduel.

Un scanner architectural interdit `node:http`, `node:https`, `node:net`,
`node:tls`, `node:dns`, `fetch`, `XMLHttpRequest` et `WebSocket` dans le Core de
production. Les assets/fonts du rendu sont locaux, contenus et hashés.

## EngineLimits certifiés

Les tests vérifient la valeur, la limite exacte et la limite +1 pour : 18 000
frames, 64 scènes, 512 layers, 20 000 caractères, 20 000 keyframes, 16 384 px,
64 MiB, 128 assets, 64 fonts, 1 024 cues et 1 024 sous-titres. Les limites
d’entrée sont contrôlées avant shaping/rendu coûteux lorsque l’information est
disponible.

## Audio, sous-titres, migrations et canonicalisation

Les fixtures non muettes certifient voix future, silence, SFX, gain, priorité,
ducking intent, ancres event/behavior/layer/voice, timing `estimated`, ainsi que
segmentation, IDs, safe zone et shaping des sous-titres. Aucun alignement réel,
karaoke ou TTS n’est simulé.

La migration MotionSpec `0.1.0 → 0.2.0` est déterministe puis idempotente ; un
ancien RenderPlan incomplet reste refusé et doit être recompilé. Les tests de
canonicalisation permutent les clés, préservent tableaux et Unicode, et refusent
les nombres non finis sans ajouter de dépendance de fuzzing.

## CI finale

`quality.yml` est le gate rapide : types, lint, unités, intégration,
déterminisme, sécurité, contamination, isolation, migrations,
canonicalisation et golden sémantique.

`motion-render.yml` est le gate Linux réel : `npm ci`, smokes Remotion, rendu
MP4 Signal + Nocturne, dix frames, régression visuelle, intégrité et upload de
`out/p1.6/certification/`. Aucun mock renderer n’est utilisé.

## Warnings, limitations et dette

Warnings attendus et non bloquants : deux `contrast.unknown_on_image`, attachés
à `visual_scene/headline`, présents dans preflight et manifeste. Aucun score
WCAG pixel n’est inventé.

Limitations connues : version FFmpeg interne non exposée ; mémoire Chromium et
FFmpeg non isolée ; MP4 binaire non comparable strictement ; validation humaine
visuelle toujours nécessaire.

Dette technique : obtenir une exposition amont stable de la version FFmpeg et
des métriques de processus enfants ; exécuter le gate sur une machine Linux
dédiée en plus des runners partagés si une baseline de performance devient
contractuelle ; migrer les actions GitHub `v4` lorsque leurs versions ciblant
Node 24 sont disponibles. GitHub avertit également que `ubuntu-latest` migrera
vers Ubuntu 26 ; l’image réellement certifiée ici reste Ubuntu 24.04.5.
