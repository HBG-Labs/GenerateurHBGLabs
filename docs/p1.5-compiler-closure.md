# P1.5 — Compiler closure

## Frontière finale

`compilePipeline()` est pur : il ne lit ni disque, ni horloge, ni réseau et n’utilise aucun hasard. Il reçoit la spec, le style résolu, le preset plateforme, le pattern, les octets de polices et d’assets et la configuration. Il produit un `RenderPlan`, un `AudioPlan`, un `SubtitlePlan`, un `QualityPreflightReport`, un `DependencyGraph` et leurs empreintes.

`compileForRender()` ajoute la frontière d’exécution. Il vérifie le render gate et les capabilities du renderer, puis construit le `ReproducibilityManifest` à partir du contexte d’exécution injecté (Git et toolchain). Après cette fonction, le renderer n’effectue aucune décision créative.

Ordre final :

1. validation des entrées et des budgets ;
2. résolution des dépendances ;
3. temporal (requis pour borner les tracks) ;
4. layout ;
5. typographie et shaping ;
6. assets ;
7. behaviors en tracks concrètes ;
8. `AudioPlan` ;
9. `SubtitlePlan` avec le moteur typographique P1.4 ;
10. quality preflight ;
11. `RenderPlan` immuable ;
12. manifeste, après injection du contexte reproductible.

## Contrats produits

- `RenderPlan 0.3.0` contient géométrie, lignes et glyphes, crops, paths, masks, tracks dotées d’IDs stables, CUT explicites et requirements renderer.
- `AudioPlan 0.2.0` contient segments voix futurs, silences, cues SFX, régions musique, gain, priorité et intention de ducking. P1.5 écrit uniquement `timing_source: estimated` et ne référence aucune voix réelle.
- `SubtitlePlan 0.2.0` contient des segments en frames, une zone sûre, un rôle de style, une police hashée et des lignes/runs/glyphes déjà mesurés. Aucun wrapping navigateur n’est permis.
- `QualityPreflightReport 0.2.0` distingue `error`, `warning` et `info`. Ses diagnostics ont un code stable, un chemin, des IDs de scène/nœud facultatifs, un contexte structuré et une action suggérée facultative.
- `DependencyGraph 0.1.0` relie scènes, layers, assets, fonts, behaviors, tracks, cues et sous-titres. Les arêtes asset/font vont de la dépendance vers ses consommateurs, ce qui permet de calculer les nœuds affectés sans implémenter encore la régénération.
- `ReproducibilityManifest 0.3.0` capture les hashes des quatre plans/rapports, le graphe, les versions pattern/registry/style, les fonts/assets, le text engine, le renderer et ses capabilities, Node, Remotion, Chromium, HarfBuzzJS, OS/arch, la configuration et Git.

Tous les IDs compilés sont dérivés du contenu canonique et des IDs de spec. L’heure, l’ordre d’insertion des clés JS et le hasard n’interviennent jamais.

## Capabilities et render gate

Le compilateur infère la liste triée parmi `TEXT`, `SHAPE`, `IMAGE`, `PATH`, `MASK`, `GROUP`, `TRANSFORM`, `OPACITY`, `CLIP`, `PATH_PROGRESS`, `COLOR`, `VARIABLE_FONT` et `CUT`, puis la hashe. Remotion déclare le catalogue complet P1.5. Une capability absente produit `renderer.capability_missing` avant bundling.

Le render gate refuse tout preflight contenant un `ERROR`. Le renderer écrit d’abord un fichier `.partial`, le valide, puis le renomme. Une erreur conserve une éventuelle sortie valide antérieure et ne crée ni manifeste mensonger ni artefact final partiel.

## Style version policy

Lorsqu’une baseline est fournie : même ID + même version + hash différent produit `style.version_not_bumped`. Le hash prouve le contenu ; la version communique le changement. Aucun des deux ne remplace l’autre. Sans baseline, la comparaison historique n’est pas inventée.

## Versions et migrations

`versionRegistry()` est le registre unique des documents versionnés. Une version courante est validée strictement. Une ancienne version n’est acceptée que lorsqu’une migration automatique nommée existe. La migration `motion-scene-spec 0.1.0 → 0.2.0` complète les versions de behaviors et transitions. Les anciens RenderPlan/AudioPlan/SubtitlePlan expérimentaux doivent être recompilés : une migration ne peut pas inventer glyphes, capabilities ou timing résolu.

Politique : seules les migrations sans perte et sans nouvelle décision créative sont automatiques. Toute autre transition retourne `version.unsupported` et exige une recompilation depuis les sources.

## Canonicalisation

Les clés d’objets sont triées récursivement, `undefined` est omis et les nombres non finis sont refusés. L’ordre des tableaux est conservé parce qu’il est sémantique (scènes, layers, keyframes, texte). Les chaînes Unicode ne sont pas normalisées silencieusement. Deux objets ne différant que par l’ordre d’insertion de leurs clés ont donc le même hash ; deux séquences différentes n’ont pas le même hash.

## Limites et sécurité

`EngineLimits` centralise les budgets agrégés : durée, scènes, layers, texte, keyframes, dimensions/octets/assets, fonts, cues et sous-titres. Les schémas conservent en plus leurs limites structurelles locales. Les dépassements produisent des diagnostics `limits.*` avant rendu.

Les invariants P1.4 restent actifs : chemins contenus dans la racine, hash obligatoire, images et fonts validées, SVG brut absent, focal points normalisés et ressources réseau interdites. Remotion reçoit uniquement des `data:` URLs construites depuis des fichiers locaux vérifiés.

## Référence et outputs

Une référence exige : tree propre, assets/fonts hashés, versions connues, aucun `ERROR`, preset identifié et renderer compatible. `reference_eligible` est calculé ; les raisons d’inéligibilité sont listées. Un tree sale reste autorisé pour le développement mais donne `git_dirty` et `reference_eligible: false`.

Le run de référence est stocké sous `out/p1.5/reference/` (ignoré Git) avec : spec, styles résolus, quatre sorties compilées par style, graphe, manifests, MP4, frames, contact sheet, preflights, visual regression et metrics. Les métriques distinguent explicitement les valeurs mesurées ; `text_shape_ms` reste `null` tant qu’il n’est pas isolé par instrumentation.

## Cache sûr et limites connues

Le bundle Remotion est mutualisé dans une instance de renderer. Les métadonnées d’assets et le shaping peuvent être mis en cache ultérieurement uniquement par hash complet d’entrée ; P1.5 n’ajoute pas de cache distribué. Aucun alignement vocal réel, TTS, provider, analyse pixel de contraste ou détection automatique de région n’est simulé. Sur image, `contrast.unknown_on_image` demeure un warning honnête. Linux reste non validé jusqu’à l’exécution de GitHub Actions.
